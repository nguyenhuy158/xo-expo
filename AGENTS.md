# Repository Guidelines

## Project Structure & Module Organization

This is a single-screen tic-tac-toe ("XO vui vẻ") Expo app (SDK 54,
React Native 0.81, React 19) for two players on one device. There is no
backend, navigation, or persistence; all state lives in `App.js` and the pure
win rule lives in `game.js`.

Folder structure:

```text
index.js           # registerRootComponent(App)
App.js             # Board state, UI and StyleSheet
game.js            # findWinner(): pure win-detection rule (no RN imports)
selfcheck.mjs      # Offline assertions for the win-detection logic
babel.config.js    # babel-preset-expo
app.json           # Expo config (bundle id, EAS project, EAS Update URL)
assets/            # App icons, splash, favicon
```

`findWinner(cells)` lives in `game.js`, which imports nothing from
`react-native`, so both `App.js` and `selfcheck.mjs` import the same rule.

`ios/`, `android/` and `build/` are generated by `expo run:*`/`expo prebuild`
and are git-ignored; never commit them. Configure native settings through
`app.json`.

## Build, Test, and Development Commands

- `pnpm install`: install dependencies (pnpm only; never use npm/yarn).
- `pnpm start` / `pnpm dev`: start the Expo dev server.
- `pnpm ios` / `pnpm android`: build and run the native app (`expo run:*`).
- `pnpm web`: start the dev server for web.
- `pnpm check`: Biome lint (the CI gate; pre-existing findings are warnings).
- `pnpm lint`: full Biome check (lint + formatting); reports formatting drift.
- `pnpm format`: apply Biome formatting (`biome format --write .`).
- `pnpm test`: run `selfcheck.mjs` with Node.
- `pnpm build`: bundle the JS for iOS with Metro into `dist/`
  (`expo export --platform ios`); no Xcode needed.

Use `pnpm` for all package commands. CI (`.github/workflows/ci.yml`) runs
`pnpm install --frozen-lockfile`, `check`, `test`, then `build`.

## Coding Style & Naming Conventions

Plain JavaScript (no TypeScript) with ES modules and JSX. Follow the existing
style in `App.js`: two-space indentation, double quotes, semicolons. Keep
pure game rules (such as `findWinner`) as named exports in `game.js`, outside
the component, and styles in a single `StyleSheet.create` at the bottom of the file. Do not
leave magic strings or numbers inline; lift them into named constants. Before
writing Expo/React Native code, check the docs for the installed SDK at
https://docs.expo.dev/versions/v54.0.0/.

## Testing Guidelines

There is no test runner. `selfcheck.mjs` uses `node:assert` to cover
`findWinner` (empty board, row, diagonal, full board without a winner).
Extend it when changing the win logic. UI changes are verified by hand in a
simulator or Expo Go. There is no browser e2e: this is a native-only app with
no deployed web URL, so the Playwright smoke used by the web repos does not apply.

## Commit & Pull Request Guidelines

History uses Conventional Commits, for example
`chore: SDK 54 + EAS Update, chuyen sang pnpm`. Keep that style. Pull
requests should include a short summary, the commands you ran, and
screenshots for visible UI changes.
